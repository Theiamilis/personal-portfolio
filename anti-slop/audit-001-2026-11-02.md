## Findings

### 1. Persistent video uploads need a server path — HIGH

**Status:** Withdrawn by the user; out of scope.

The local project is static HTML/CSS with image assets; it has no PHP, upload endpoint, account check, or file storage. A file picker can preview a video in the current browser, but it cannot save that video into the website for later visitors. Adding a persistent uploader without storage and access control would leave a control that appears to work but loses its content. *(R-26, C-2)*

**Suggested fix:** Decide whether video selection is only for local preview or whether videos should be saved to the site. Persistent uploads need a backend, storage, and upload access rules.

### 2. The portfolio does not yet have the reference's quick-link area — MEDIUM

**Status:** Approved through the user's request to make the site like the reference.

The current page presents a résumé and a project case study. Its contact section has placeholders, while the reference makes curated destinations easy to scan. A dedicated links area can borrow that structure while retaining the current blue visual style. Real destinations are still needed before links can be filled in. *(R-05, R-24)*

**Suggested fix:** Present the existing site sections through a clickable wheel and show the selected section alongside it. Add external social links only when the owner supplies their URLs.

### 3. Videos need their own portfolio section — MEDIUM

**Status:** Withdrawn by the user; out of scope.

The current portfolio has a project card with a still image and expandable case-study details. It has no video collection. Adding videos into the same image list would make the media types harder to browse and would conflict with the requested separation. *(R-05)*

**Suggested fix:** Create a distinct Videos section with its own upload/list area, separate from photo or project imagery.
